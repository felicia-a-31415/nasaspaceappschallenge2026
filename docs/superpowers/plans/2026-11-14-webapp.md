# Fire Calendar Web App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A web app where a click on a map plus a radius and a month range returns a plain sentence, a years-by-months fire calendar and downloads, instantly inside Canada and on demand elsewhere.

**Architecture:** The existing `harmonize` package gains a both-sensor burning-squares table, a circle query and a FIRMS API client. A FastAPI server in `server/` loads Canada's tables once, answers circle queries by calling `harmonize`, and runs a one-at-a-time fetch queue for places outside Canada. A React page in `web/` draws the map, card and calendar from the server's JSON; the server also serves the built page.

**Tech Stack:** Python 3 (pandas, numpy, pyarrow, shapely, FastAPI, uvicorn, httpx, python-dotenv, pytest). TypeScript, React, Vite, Leaflet via react-leaflet, vitest. Google Cloud Run for hosting.

**Spec:** `docs/superpowers/specs/2026-11-14-webapp-design.md` (read it first). Background: `docs/superpowers/specs/2026-11-14-harmonization-design.md`.

- `FIRMS_MAP_KEY` is read from the environment or `.env`. It never appears in code, logs, test fixtures, URLs printed to the console, the browser, or git.
- No file over 100 MB is committed. `data/canada/`, `outputs/canada/hotspots.parquet`, `cache/`, `web/node_modules/`, `web/dist/` are git-ignored.
- Source CSVs are never modified.
- Square size is 0.1 degrees. VIIRS takes over in `2012-02`. Radii are 50, 100, 200 km, default 100. Month ranges are whole months, `YYYY-MM`.
- Every number shown or downloaded carries whether it is observed or estimated. The page and the monthly CSV come from the same server function.
- FIRMS budget: 5,000 units per 10 minutes. Never start a batch that would pass 4,800.
- Plain words in everything the user reads. No "cell-days", "NRT", "SP" or "calibration" on the page.

## Review Focus

1. **A place with no fire at all** (open ocean, city centre): the user expects a calm sentence and an empty calendar, not an error or "NaN times". Pinned in Task 3.
2. **FIRMS answers with an error message instead of data** (bad key, budget spent, server hiccup; it can arrive with HTTP 200): the user expects a retry and then a clear "could not fetch", never a year silently recorded as fire-free. Pinned in Task 7.
3. **A click near the edge of the world map** (longitude near ±180, latitude near the poles) outside Canada: the user expects an answer or a polite "not available here", not a crashed fetch. Pinned in Task 8.
4. **The same outside-Canada place clicked twice, or by two people**: the user expects one fetch, shared progress, and an instant answer afterwards. Pinned in Task 8.
5. **A month range that makes no sense or is tiny** (from after to, a single month, a range ending in a month with no data yet): the user expects a clear message or a sensible answer. Pinned in Tasks 3 and 4.

### Task 3: Answer for a circle

**Files:**
- Create: `harmonize/query.py`
- Test: `tests/test_query.py`

**Interfaces:**
- Consumes: `cell_days.parquet` layout (Task 1); `calibrate.lift(modis, model)`; `run.SWITCH`, `run.TERRA_ONLY_END`.
- Produces:
  - `RADII_KM = (50, 100, 200)`
  - `cells_in_circle(cd, lat, lon, radius_km) -> pd.DataFrame`: rows of `cd` whose square **centre** (`cell_lat + 0.05`, `cell_lon + 0.05`) is within `radius_km` by great-circle distance.
  - `circle_monthly(cd, model, lat, lon, radius_km, start, end, data_start=None, data_end=None) -> pd.DataFrame`: index monthly `PeriodIndex` named `month` from `start` to `end` clipped to `[data_start, data_end]` (defaults: first and last month in `cd`); columns `activity`, `low`, `high` (floats), `estimated`, `terra_only` (bools), `median` (float: median `activity` of that calendar month over every year in the full data period, computed from this same circle).
  - `summarize(monthly_full, start, end) -> dict | None` with keys `year`, `months` (list of month numbers), `total`, `median`, `ratio` (float or `None`), `rank`, `years_compared`, `sentence`. `monthly_full` is `circle_monthly` over the whole data period.
  - `monthly_csv(monthly) -> str`: columns `month,activity,low,high,estimated,terra_only,median`, activity values rounded to 1 decimal.

Rules the tests pin:

- Before `2012-02`: `activity, low, high = lift(MODIS count)`, except a MODIS count of 0 gives `0, 0, 0`. From `2012-02`: all three equal the VIIRS count; `estimated` is False.
- `summarize` takes the last calendar year touched by `[start, end]`, and the months of that year inside the range. It compares that year's total with the same months in every other year of the full period that has all of those months. `rank` is 1 for the highest. Fewer than 5 comparison years returns `None`.
- Sentence copy, with `Y` the year and `R` the ratio shown as a whole number from 10 up and one decimal below:
  - total 0 and median 0: `"No fire was detected here in Y. That is normal for this place."`
  - total above 0 and median 0: `"Y had fire here. In most years there is none."`
  - `R >= 1.5`: `"Y had R times the usual amount of fire here."` followed by `" The most since P."` where `P` is the latest earlier year with a higher total, or `" The most since records began in F."` when rank is 1 (`F` is the first comparison year).
  - `R <= 0.67`: `"Y had less fire than usual here, about N% of a normal year."`
  - otherwise: `"Y was about normal for fire here."`
  - When the months are not the full year, replace `"Y"` wherever it appears in the sentence with `"M1 to M2 Y"` using month names (`"May to September 2023"`), or `"M1 Y"` for one month.

**Files:**

**Interfaces:**
- Consumes: `query.cells_in_circle`, `grid.monthly_counts`, `calibrate.fit`, `calibrate.lift`, `run.OVERLAP`.
- Produces: `circle_validation(cd, radii_km=(50, 100, 200), n=300, seed=0) -> pd.DataFrame`, one row per radius: `radius_km`, `circle_years` (count used), `median_err_none`, `median_err_curve` (median absolute percent error of the predicted yearly VIIRS total), `within_2x_curve` (percent of circle-years where the prediction is between half and double the actual).

Method, fixed here because tests cannot determine it:

1. Circle centres: `n` squares drawn at random (seeded) from squares where VIIRS detected fire at least once in the overlap period.
2. For each overlap year: fit the curve on the **whole region's** monthly counts with that year removed (as `leave_one_year_out` does). For each circle, lift that circle's monthly MODIS counts for the hidden year (zero stays zero), sum, and compare with the circle's VIIRS total for that year.
3. Use only circle-years whose actual VIIRS total is at least 10; smaller totals make percentages meaningless.

**Interfaces:**
- Produces:
  - `SOURCES = {"modis": ("MODIS_SP", "MODIS_NRT"), "viirs_snpp": ("VIIRS_SNPP_SP", "VIIRS_SNPP_NRT"), "viirs_noaa20": ("VIIRS_NOAA20_SP", "VIIRS_NOAA20_NRT")}`
  - `class FirmsError(Exception)`
  - `load_key() -> str` (environment first, then `.env`; raises `FirmsError` with a plain message if missing).
  - `budget_used(key) -> int` from `https://firms.modaps.eosdis.nasa.gov/mapserver/mapkey_status/?MAP_KEY=<key>` (`current_transactions`).
  - `availability(key) -> dict[str, tuple[date, date]]` from `/api/data_availability/csv/<key>/ALL`.
  - `fetch(dataset: str, box: tuple[float, float, float, float], start: date, end: date, key: str, workers: int = 20) -> pd.DataFrame`: all hotspots for `dataset` in `box` (west, south, east, north) from `start` to `end` inclusive, in the **download-file column layout** that `schema.unify` accepts. It picks the standard source for dates it covers and the recent source after that, per `availability`. Empty result is an empty frame with the right columns.
  - `wait_for_budget(key, needed: int, limit: int = 4800, sleep=time.sleep) -> None`: returns when `budget_used + needed <= limit`, sleeping 30 seconds between checks.
- Request URL: `https://firms.modaps.eosdis.nasa.gov/api/area/csv/<key>/<SOURCE>/<west,south,east,north>/<days 1..5>/<YYYY-MM-DD>`.
- Cost estimate used by callers: 2 units per day requested.

What the client must handle:

- The API's VIIRS CSV names the brightness columns `bright_ti4` and `bright_ti5`; the download files use `brightness` and `bright_t31`. Rename. Recent sources have no `type` column; leave it absent (`unify` already flags that). Before writing the fixtures, fetch one real five-day sample for each sensor (inside a summer week in Quebec) and diff its header against `data/quebec/*/fire_archive_*.csv`; handle every difference found and note them in a comment. Save trimmed copies (20 rows) as the fixtures. The key must not appear in them.
- A response is valid only if its first line starts with `latitude,` (or it is that header alone). Anything else (`Invalid MAP_KEY.`, `Exceeding allowed transaction limit.`, HTML, timeouts, HTTP 4xx/5xx) is retried up to 3 times with 2, 5, 10 second waits, then raises `FirmsError`. Error messages have the key replaced by `<key>`.

- Produces:
  - `box_for(lat, lon) -> tuple[float, float, float, float] | None`: a 10 by 10 degree box (west, south, east, north) centred on the click, corners rounded to whole degrees, shifted to stay within longitude ±180 and latitude ±80. Returns `None` if `abs(lat) > 75` (no fetch offered there).
  - `class Places(cache_dir: Path, model: dict, fetch=firms.fetch, key: str | None = None)` with:
    - `find(lat, lon, radius_km) -> PlaceState | None`: a saved or in-progress box that contains the whole circle.
    - `request(lat, lon, radius_km) -> PlaceState`: `find`, or create a new place and queue it.
    - `table(state) -> Table`: the burning-squares fetched so far, with `curve_source="canada"`, `data_start` the earliest fetched month.
    - `start()` / `stop()`: the single worker thread.
  - `PlaceState`: `id`, `box`, `status` (`"queued"`, `"fetching"`, `"fetched"`, `"failed"`), `years_done`, `years_total`, `queue_position`, `error` (plain sentence or None).

- Fetch steps, in order, one calendar year each: `viirs_snpp` from the current year back to 2012; `viirs_noaa20` only for dates after Suomi NPP's last available date; then `modis` from 2011 back to 2000. Before each step: `wait_for_budget(key, needed=2 * days_in_step)`. After each step: unify, clean, grid, append, save, mark the step finished.
- A step that raises `FirmsError` is retried once after 60 seconds; a second failure sets `status="failed"` with `error="NASA's fire data service did not answer. Try again in a few minutes."` and the worker moves to the next place. A later `request` for a failed place re-queues it and resumes from the finished steps.
- On start-up, places whose `meta.json` says queued or fetching are re-queued.
- `/api/activity` for `"outside"` circles now: `box_for` is `None` gives `coverage: "outside"` with `detail: "Fire history is not available this far north or south."`; otherwise `request(...)` and answer from `table(state)` with `coverage` equal to the status, `progress` filled, `summary` computed only when at least 5 comparison years are present, and `curve_source: "canada"`. `status == "failed"` returns `coverage: "outside"` with the error as `detail`.
